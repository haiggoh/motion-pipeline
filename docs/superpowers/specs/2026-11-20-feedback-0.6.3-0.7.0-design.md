# motion-pipeline — feedback round after 0.6.2 (design)

Source: the user's hands-on test of v0.6.2 via `motion-pipeline-dev` in Apple Terminal
(`~/.claude/plans/motion-pipeline-0.6.2-feedback.md`). Decisions below marked **(user)** were
chosen by the user on 2026-11-20; everything else is the designer's call and may be changed
by the builder if it turns out wrong, with a note in the plan's ledger.

## Intent

The menu should be usable by a non-technical editor without friction: no inputs that accept
garbage, no errors that tell you to do something you can't, no step that silently depends
on a later step, no greyed-out row without a reason, no painted grey blocks that break the
terminal-native look (csl style, `base.py`).

## Shipping shape (user)

Two releases, in order, each shipped end to end (gates → merge → tag → GitHub release →
homebrew-tap bump PR merged → refreshed install → dogfood):

- **0.6.3 — bug fixes** (part A). The tap bump itself is automatic: `.rtc/post-release.sh`
  rewrites url+sha256 in the brew-registered tap checkout and pushes (verified: tap
  origin/main is at `95469db motion-pipeline 0.6.2`). The 0.7.0 `depends_on "whisper-cpp"`
  change is a formula EDIT beyond url/sha and goes through the tap's branch + PR +
  merge-commit pattern.
- **0.7.0 — features** (part B).

## Part A — 0.6.3 bug fixes (root causes verified 2026-11-20 against 7e6fa58)

A1. **Stray `p` at startup.** Textual 8.2.8 `LinuxDriver._query_in_band_window_resize`
writes `ESC[?2048$p` (linux_driver.py:157); Apple Terminal prints the `p`. motion-pipeline
has no driver override. Fix: port free-agents' `AppleTerminalSafeDriver`
(`~/ClaudeWorkspace/free-agents/bin/session_picker_terminal.py`) and pass it via
`super().__init__(driver_class=...)` in `MenuAppBase.__init__` (a class attribute is
overwritten by `App.__init__`). Delivery-level test: PTY run with
`TERM_PROGRAM=Apple_Terminal` asserts the 2048 query is never written.

A2. **Voiceover drop lands in the transcript field.** `SubmenuScreen.on_paste` sends a drop
on a non-Input widget to the FIRST `PathInput`, and then focuses it; a drop while an Input
has focus goes to that Input. Either way the target is chosen by focus, which the user
cannot see or control during a Finder drag. Fix: route a drop by WHAT was dropped. Each
`PathInput` declares the extensions it accepts (transcript: txt/md/rtf/doc/docx/pdf;
voiceover: wav/mp3/m4a/aif/aiff/flac/mov/mp4; folders: fields that take folders). A drop
goes to the single field that accepts it; only when zero or several fields accept it does
focus decide (current behaviour). Applies on every screen with path fields.
(Assumed, not reproduced: the user's second drop went to the transcript field because the
first drop had left focus there. The fix covers both routes.)

A3. **Grey block behind the job log** (background test + render). `RichLog` ships
`background: $surface` and a `:focus` tint; `CSL_CSS` only overrides `Log`. Fix: add
`RichLog` (and `RichLog:focus`) to the csl rules with `ansi_default` + `background-tint: 0%`.
Test asserts the computed background on the mounted widget (the hover lesson: assert
computed style, not CSS text).

A4. **Background test fails without a transcript.** `render_cli.render()` always calls
`prepare_inputs()` (requires transcript.txt), and `generate()` builds scenes from the
transcript model + timing. Step 4 must not depend on step 5. Fix (user): in `--mode test`,
when no readable transcript exists, use a built-in sample transcript (one section: a
headline-length line + one body line, language-neutral) with estimated timings, written to
a scratch location so the project's own `transcript_model.json` / `timing.json` are never
created or overwritten by a test render. When a real transcript exists, the test render
uses its first section, as now. Same render code path (render_scene.sh), as the anti-goal
in app.py requires.

A5. **"Add motion graphics" stays greyed out, no reason shown.** Three defects in a chain:
(a) `InputsScreen._on_timing_saved` (app.py:324) is dead code: the prepare-only worker is
never observed, so the status stays "computing timings…" forever. (b) The worker runs
`subprocess.run(..., capture_output=True)` and never reads the exit code, so a failure
(missing transcript, bad VO, contrast error inside generate) is swallowed. (c)
`MenuScreen` evaluates `graphics_step_enabled()` only in `compose()`; returning to the
menu (`on_screen_resume`) refreshes only the subtitle. Fix: run prepare-only through
`jobs.run_command` (streams lines, honest final line, `on_finish(rc)`); on success report
the counts, on failure show the named error; re-evaluate the gate in
`MenuScreen.on_screen_resume`; when disabled, the row's label carries the reason
("6) Add motion graphics — needs saved timings (step 5)").

A6. **Fonts beginning with `.`.** These are not stray files: 73 families on this Mac are
real faces inside Apple system collections whose family name starts with `.` — Apple's
marker for private UI/fallback faces (e.g. `.ADT Slab Numeric` in ADTNumeric.ttc,
`.Al Bayan PUA`). Font Book hides them. Fix: `font_index.families()` (or the screen)
drops families whose name starts with `.`; the cache keeps them (no rescan needed).

A7. Additional bugs found by the code review pass, verified by reading the code:
- X1: `align.align()` decodes the voiceover twice (`_decode_pcm` + `_envelope` at the top
  are discarded; the voice-band ffmpeg decode replaces them) — doubles part of the
  "computing timings" wait.
- X2: `InputsScreen.on_mount` and `FontsScreen._prefill_from_project` swallow a corrupt or
  invalid `project.json` (`except Exception`) and show defaults as if they were real state.
Rejected after checking (not bugs): cancel races in jobs.py (on_finish is skipped when
cancelled; a cancel racing Popen is re-sent), engine-status timing, project picker load
errors (entries are pre-validated), OWNED_KEYS 'graphics'. Each fix gets a failing test first.

Builder-check answers (designer's calls unless stated):
- Contrast pairs are exactly the two in `scheme.py`: text on background_dark ≥ 4.5:1 and
  accent on background_dark ≥ 3.0:1 (existing constants CONTRAST_TEXT / CONTRAST_ACCENT).
- Zones already exist: `project.json` `zones[]`, each `{section, rect:[x,y,w,h], aspect}`;
  zones of other aspects stay on disk and are inactive. B3 is UI only, no schema change.
- Folder drops: a PathInput declares `accepts_dirs`; folders go only to such fields. A
  multi-item drop uses the first item and says so in the field's status
  ("2 items dropped — used the first").
- `contrast_override` lives in the file it was saved into (base scheme.json or a variant
  overlay); the effective value for a variant is the overlay's if set, else the base's. A
  variant whose effective colours pass prints no warning regardless of the flag.
- Background test with a voiceover but no transcript: the sample is used and the VO is
  ignored (the scratch project's copy of project.json has `vo: null`).
- The free-agents repo is present on this machine (`~/ClaudeWorkspace/free-agents`); port
  the driver from it.

## Part B — 0.7.0 features

### B1. CI colours

- Hex field: the `#` is a fixed dimmed label OUTSIDE the field (like H/S/L); the field
  takes at most 6 characters and only `0-9a-fA-F` (Textual `Input(restrict=…,
  max_length=6)`). A pasted `#ff6a00` is accepted (strip `#` before the restrict check —
  verify how `restrict` treats pastes; if it rejects the whole paste, handle `_on_paste`).
- 3 hex digits are read as the short form (`fff` → `#ffffff`) by `normalise_hex`; the swatch
  and H/S/L update at 3 and at 6 digits; 1, 2, 4, 5 digits = incomplete (empty swatch, no
  error until Save/Derive).
- H/S/L fields: digits only; H max 3 chars and 0–360, S/L max 3 chars and 0–100 (values
  above the range are refused at input, not clamped silently).
- Contrast failures (user):
  - each colour row involved in a failing pair gets a red `!` in front of its label;
  - the message says what fails and what will fix it, in words the user can act on:
    `text on background dark: 1.07:1 — needs at least 4.5:1` and
    `Fix: darken background dark → #6b6b6b (reaches 4.5:1)`;
  - new action **Fix contrast**: computes, for each failing pair, the smallest OKLab
    lightness change (hue and chroma kept) on EITHER the foreground (text/accent) OR
    background_dark that reaches the floor, and picks the smaller of the two (user:
    "smallest change wins"). One fix must not break the other pair: re-check both pairs
    after applying; if the smallest fix for one breaks the other, choose the next option.
    The proposed change is shown in the message before the button is used; after applying,
    the rows update and Save is still a separate step. Undo is the existing Back-without-
    saving, plus the previous values shown in the status line.
  - new action **Save anyway (ignore contrast)**: saves with `"contrast_override": true` in
    scheme.json (or the variant overlay). `derive_palette` honours the flag everywhere it is
    called (render path included) — downgrade the raise to a printed warning naming the pair.
    Changing a colour that fixes the contrast clears the flag on the next save.

### B2. Font

- The `Headline/Label/Body/Emphasis/All roles` dropdown is replaced by a checkbox
  **Apply to all roles** (default ON, user). Unticked: clicking (or Enter on) a role row
  selects it as the edit target, and that row is highlighted (soft-blue, csl style);
  picking a family then applies only to the highlighted role.
- Preview (user: bigger inline + live window): the inline half-block preview gets the full
  editor width and the remaining height (one line per role, larger px sizes). The sharp PNG
  is re-rendered on every preview change; Quick Look / Preview, once opened by the button,
  picks up the new file (verify qlmanage refreshes on file change; if it doesn't, open the
  PNG with `open -a Preview`, which reloads changed files).

### B3. Keep-out zones (user: both views)

- One short explanation at the top of the screen: what a zone is, that it is anchored to a
  transcript section, that the rect is in frame pixels of the project's aspect.
- Frame map: a box of the project's aspect drawn with box-drawing characters, each zone of
  the current aspect a labelled rectangle (section name), the selected zone highlighted;
  updates live as the rect field is edited (invalid rect → map shows the last valid state
  plus the error).
- When a background-test frame exists (`renders/.../_test_frame.png`), an "Overlay on test
  frame" view draws the zones over the half-block image.

### B4. Transcript + voiceover

- Speech model is a dependency, not a chore (user: formula dep + first-launch fetch):
  homebrew-tap formula gains `depends_on "whisper-cpp"`; on menu launch, if no model is
  present, `ggml-base.bin` is fetched in the background (sha256-pinned in the repo, progress
  shown in the Transcript screen's engine line, atomic write to
  `~/.cache/motion-pipeline/models`). The "Install speech model" row is removed; a failed
  fetch shows a "Retry speech model download" row and the error. Tests never download
  (existing rule in align_whisper.py) — the fetch is injected/mocked.
- Computing timings shows a spinner (LoadingIndicator in place, never a bottom status row)
  and a progress bar fed by stage lines from `render_cli --prepare-only`
  (`progress: <done>/<total> <stage>`; whisper-cli's own progress output where available).
- Drag and drop routes by file type (A2).
- Transcript formats (user: map real headings): `.txt` and `.md` native (`#` headings,
  `*emphasis*`); `.docx` — Heading-styled paragraphs → `# ` sections, bold/italic runs →
  `*emphasis*` (stdlib zip+XML, or textutil if it preserves headings — builder verifies);
  `.rtf`/`.doc` via macOS `textutil -convert` (headings only if the conversion carries
  them); `.pdf` via `pypdf` (new runtime dependency in pyproject) as plain text. After
  loading, the screen shows `N sections, M words`. The source file is never modified; the
  freshness fingerprint keeps hashing the source bytes.
- Language default is **Auto-detect** for new projects; existing projects keep their saved
  value.
- wpm: without a voiceover it stays an editable field (it is the only timing source); with a
  voiceover attached it becomes a read-only indicator of the measured rate after timings are
  computed (`measured 152 wpm`), and the saved wpm is not used for timing.

### B5. Render screen

Same as A3 (no painted grey). No other change.

## Non-goals

- No graphics protocol (Kitty/Sixel/iTerm) support — the user's terminal is Apple Terminal.
- No change to the render code path, masters or gates beyond A4's sample input.
- No menu reordering (A4 removes the chronological dependency instead).

## Anti-goals

- A test render that writes or overwrites the project's real timing/transcript model.
- Any input that silently changes what the user typed (clamping, truncating a paste)
  without showing it.
- A greyed-out row with no visible reason.
- A green pilot test standing in for a rendered-output check: every UI claim gets a
  delivery-level test (rendered plain text / computed style / PTY run), per the repo's
  `.claude/rules/dev-tui-tests-need-visible-geometry-and-installed-artifact.md`.
